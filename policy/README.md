# 策略（Policy）

> 本目录存放监督闭环使用的规则与注入模板。**初始化阶段为占位说明，规则正文将在 Phase 2 落地。**

## 规则来源

策略基线来自机器本地的 Codex 全局行为规范（`AGENTS.md`）与配套的「防御性编程审计与规范设计」研究：

- 40 类违规模式，按 A–H 分组：

| 组 | 主题 |
|---|---|
| A | 内部契约（冗余类型检查、必需字段按可选读、测试替身迁就、重复校验） |
| B | 默认值与未知值（缺失/零值混淆、非法输入"修好"、未知元数据推定正常、伪造时间戳） |
| C | 异常语义（大范围捕获、吞异常、失败折叠为空、异常只剩文本、错误文本当状态） |
| D | 状态与部分完成（未知状态默认健康、受理冒充完成、部分执行被抹掉、二次故障覆盖首故障） |
| E | 重试与兼容（虚构历史兼容、异常猜签名、所有错误都重试、多层/无预算重试、副作用盲重放） |
| F | 回退与伪成功（静默切 mock、旧缓存冒充新成功、删失败分母、多层默认值洗根因、无需求备用实现） |
| G | 参数与缩水（极端保守值、擅自缩规模、静默限幅、经验值伪装硬限制、门限叠加失效） |
| H | 验收与流程（为绿灯改测试、模拟证据升级、补丁代替根因、编造限制、流程性过度防御） |

- 另有**行动偏好**（Phase 2 补充）：授权内直接推进、允许必要重构、不以确认代替工作、不做想象兼容、不用"可能的风险"缩水目标——用于纠正"畏手畏脚/带着镣铐"的行为。

## 判定原则

1. 出现某个 API 只是线索，是否违规取决于契约、边界、失败语义与实际影响。
2. 真实防御必须保留：不可信输入校验、权限/长度边界、事务、并发同步、资源释放、设备限位、有证据的恢复策略。
3. 规则以「正例/反例」成对维护，回归测试必须保证正例不被误报。
